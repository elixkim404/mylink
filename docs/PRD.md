## 1. 배경 및 목적 (Background & Objective)

링크트리(Linktree)는 SNS 바이오 칸에 들어가는 링크 집합 페이지로, 크리에이터·학생·개인 모두가 손쉽게 "내 모든 채널"을 한 곳에 모아 공유할 수 있게 해 준다.

**MyLink**는 이 링크 인 바이오 카테고리의 국내 클론 서비스로, 다음 목표를 가진다.

- **누구나** 간편 가입 후 나만의 퍼블릭 프로필 페이지(`mylink.app/@handle`)를 만든다.
- 링크 관리를 **모바일에서도 쉽고 직관적**으로 할 수 있게 한다.
- **토스 디자인 시스템(TDS)** 기반의 깔끔하고 신뢰감 있는 UI를 제공한다.
- 추후 분석·수익화·API 기능을 올릴 수 있는 **확장 가능한 기반**을 마련한다.

## 2. 타깃 사용자 (Target Users)

| 페르소나 | 설명 | 주요 니즈 |
|---|---|---|
| **대학생 / 새내기** | 깃허브·블로그·SNS 등 채널이 늘어나는 시기 | 빠른 가입, 간편한 링크 추가 |

## 3. 개발 단계 (Development Phases)

> 백엔드 연동 전에 UI·UX를 먼저 검증하고, 이후 단계에서 실제 서버와 연결한다.

### Phase 0 — UI 프로토타입 (현재 단계)

**목표**: 백엔드 없이 `localStorage`만으로 핵심 흐름을 검증한다.

| # | 기능 | 비고 |
|---|---|---|
| P0-01 | 퍼블릭 프로필 페이지 (`/`) | 아바타·이름·소개·링크 목록 표시 |
| P0-02 | 프로필 & 링크 편집 (`/edit`) | localStorage 읽기/쓰기 |
| P0-03 | 링크 CRUD + DnD 순서 변경 | 로컬 상태만 사용 |
| P0-04 | 링크 ON/OFF 토글 | 로컬 상태만 사용 |
| P0-05 | 프로필 URL 복사 & QR 코드 | 클라이언트 전용 |

**데이터 저장소**: `localStorage` (`mylink_data` 키)  
**인증**: 없음 (단일 사용자 전제)  
**통계/대시보드**: Phase 0 범위 외

### Phase 1 — MVP (멀티유저 SaaS)

**목표**: Supabase 연동, 실제 멀티유저 서비스 출시.

| # | 기능 영역 | 설명 |
|---|---|---|
| F-01 | 인증 | 소셜 로그인(Google·GitHub·카카오), 이메일+패스워드 |
| F-02 | 핸들 설정 | 가입 직후 `@handle` 선택 (영문·숫자·언더스코어, 3-30자) |
| F-03 | 프로필 편집 | 이름, 한 줄 소개, 아바타 이미지 업로드 |
| F-04 | 링크 CRUD | 제목·URL·썸네일 아이콘 등록/수정/삭제 |
| F-05 | 링크 순서 변경 | 드래그 앤 드롭(모바일 터치 포함) |
| F-06 | 링크 ON/OFF | 개별 링크 활성화/비활성화 토글 |
| F-07 | 퍼블릭 페이지 | `/@handle` 공개 프로필 페이지 (비로그인 접근 가능) |

| F-09 | 기본 통계 | 총 방문자 수, 링크별 클릭 수 (지난 30일) |
| F-10 | 반응형 레이아웃 | 모바일 퍼스트, 태블릿·데스크탑 대응 |

## 4. 사용자 스토리 (User Stories)

### 인증 & 온보딩 (Phase 1)

```
US-01  비가입자로서, 구글 계정 하나로 30초 안에 가입을 완료하고 싶다.
       → 소셜 로그인 후 핸들 설정 화면 진입까지 화면 수 3개 이하.

US-02  가입자로서, 내 @handle 이 이미 사용 중인지 실시간으로 확인하고 싶다.
       → 타이핑 중 중복 여부 즉시 표시(debounce 500ms).
```

### 링크 관리

```
US-03  사용자로서, 링크를 새로 추가할 때 URL만 붙여넣으면
       제목이 자동으로 채워지면 좋겠다. (OGP meta fetch)

US-04  사용자로서, 화면에서 링크를 위아래로 드래그해
       노출 순서를 바꿀 수 있어야 한다.

US-05  사용자로서, 링크를 ON/OFF할 수 있어서
       삭제하지 않고 임시로 숨길 수 있어야 한다.
```

### 퍼블릭 페이지 & 공유

```
US-06  방문자로서, mylink.app/@handle 에 접근하면
       프로필 사진·이름·소개·링크 목록을 볼 수 있어야 한다.

US-07  사용자로서, QR 코드를 다운로드받아 명함·포스터에 붙이고 싶다.
```

### 통계 (Phase 1)

```
US-08  로그인 사용자로서, 대시보드에서 지난 30일간
       페이지 방문자 수와 링크별 클릭 수를 확인하고 싶다.
```

### 👤 소유자 시나리오 (Owner / Creator)

> 프로필을 만들고 링크를 관리·배포하며 통계를 확인하는 로그인 유저의 관점

#### SC-U01. 초고속 온보딩 및 첫 핸들 선점 (Phase 1)

**페르소나**: 이준서 (26세, 사이드 프로젝트 개발자 / 깃허브·노션·블로그 링크를 한곳에 모으고 싶음)  
**상황**: 노트북으로 랜딩 페이지에 유입되어 1분 안에 나만의 주소를 만들고자 함

1. 랜딩 페이지(`/`)의 **"30초 만에 내 링크 만들기"** CTA 버튼을 클릭한다.
2. Google / 카카오 간편 로그인을 진행하여 별도 복잡한 폼 없이 가입을 마친다.
3. 온보딩 화면(`/onboarding`)에서 원하는 핸들(`@junseop`)을 입력한다.
   - 디바운스(500ms)로 실시간 중복 체크가 동작하여 "사용 가능한 핸들이에요 ✅" 메시지를 확인한다.
4. 이름, 한 줄 소개, 프로필 사진을 등록하고 **[완료]**를 누른다.
5. 즉시 대시보드(`/dashboard`)로 이동하며 온보딩 축하 토스트와 함께 빈 링크 등록 카드가 나타난다.

**성공 기준**: 랜딩 클릭부터 대시보드 진입까지 1분 이내 완료, 중복 체크 응답 지연 ≤ 300ms

---

#### SC-U02. 스마트 OGP를 활용한 링크 추가 (Phase 0·1)

**페르소나**: 김예현 (20세, 컴공과 새내기 / 깃허브, 노션 포트폴리오 링크 등록)  
**상황**: 모바일 브라우저에서 새로 작성한 노션 포트폴리오 링크를 빠르게 추가하려고 함

1. 관리자 화면에서 **[+ 새 링크 추가]** 버튼을 탭한다.
2. 클립보드에 복사해 둔 노션 포트폴리오 URL을 붙여넣는다.
3. 백그라운드에서 OGP 메타데이터를 즉시 페칭하여 링크 제목이 "예현의 개발 포트폴리오"로 자동 입력된다.
4. 기본 파비콘 또는 원하는 이모지(`📝`)를 탭하여 대표 아이콘으로 설정한다.
5. **[등록]** 버튼을 누르면 목록 최상단에 새 링크 카드가 즉시 추가된다.

**성공 기준**: URL 붙여넣기 후 OGP 제목 자동 추출 성공률 ≥ 90%, 추출 시간 ≤ 1.2s

---

#### SC-U03. 모바일 DnD 순서 변경 및 링크 임시 보관 (Phase 0·1)

**페르소나**: 최유리 (29세, SNS 인플루언서 / 기간 한정 이벤트 링크를 자주 올리고 내림)  
**상황**: 진행 중이던 공구 이벤트가 끝나 링크를 임시로 숨기고, 상시 유튜브 링크를 맨 위로 올리고 싶음

1. 대시보드 링크 목록에서 "공구 할인 링크" 카드의 **[활성/비활성 토글]** 스위치를 끈다.
   - 카드가 반투명(회색조)으로 전환되며 퍼블릭 페이지에서 즉시 비노출 처리된다. (삭제하지 않고 안전하게 보관)
2. 세 번째에 위치한 "유튜브 채널" 카드의 드래그 핸들(Drag Handle)을 터치하여 길게 누른다.
3. 햅틱 피드백과 함께 카드가 플로팅되며, 첫 번째 위치로 드래그하여 놓는다.
4. `useOptimistic`을 통해 화면이 즉각 재정렬되고 백그라운드에서 변경된 순서(`sort_order`)가 동기화된다.

**성공 기준**: 모바일 터치 드래그 반응 지연 체감 제로, 손 뗀 후 0.3초 이내 정렬 확정

---

#### SC-U04. 프로필 다채널 배포 및 QR 코드 추출 (Phase 0·1)

**페르소나**: 이준서 (개발자 컨퍼런스 네트워킹 세션 참가 중)  
**상황**: 현장에서 만난 동료들에게 긴 URL을 말로 부르는 대신 시각적으로 빠르게 공유하고 싶음

1. 프로필 관리 헤더의 **[공유하기]** 아이콘을 누른다.
2. 모달 시트가 열리며 2가지 옵션이 제공된다:
   - **[링크 복사]**: 클립보드에 `mylink.app/@junseop` 복사 + 토스트("링크가 복사되었어요") 노출.
   - **[QR 코드 보기/저장]**: 생성된 고대비 QR 코드를 화면 가득 띄우거나 PNG 이미지로 다운로드.
3. 스마트폰 화면에 QR 코드를 띄워 상대방의 카메라 스캔을 유도한다.

**성공 기준**: 공유 버튼 터치부터 QR 전체화면 렌더링까지 2탭 이내, 0.5초 이내 QR 렌더링 완료

---

#### SC-U05. 실시간 클릭 통계 확인 및 링크 최적화 (Phase 1)

**페르소나**: 최유리 (마케터)  
**상황**: 인스타그램 프로필 바이오에 링크를 걸어둔 후 지난 주말 유입 성과를 확인하고자 함

1. 대시보드의 **[통계 (Analytics)]** 탭으로 이동한다.
2. 최근 30일간의 **총 프로필 방문 횟수(PV)**와 **링크별 누적 클릭 수**를 확인한다.
3. "유튜브 링크"는 1,200회 클릭된 반면, 하단의 "개인 블로그"는 12회에 불과함을 발견한다.
4. 클릭률이 낮은 블로그 링크를 아래로 내리거나 새 프로모션 링크로 교체하기로 결정한다.

**성공 기준**: 통계 집계 데이터 로딩 시간 ≤ 1초, 클릭 누락 오차율 ≤ 1%

#### SC-V01. SNS 인앱 브라우저를 통한 프로필 탐색 및 이동 (Phase 0·1)

**페르소나**: 박민지 (24세, 인스타그램 팔로워)  
**상황**: 인스타그램 프로필 바이오의 `mylink.app/@yuri_style` 링크를 탭함

1. 인스타그램 인앱 브라우저에서 프로필 페이지가 로드된다.
   - SSR/ISR로 정적 최적화되어 1.5초 이내에 프로필 사진, 닉네임, 깔끔한 카드형 링크 목록이 나타난다.
2. 레이아웃 흔들림(CLS) 없이 신뢰감 있는 TDS 모바일 뷰를 마주한다.
3. 가장 상단에 강조된 "최신 브이로그 보러가기" 링크 카드를 탭한다.
4. 클릭 이벤트가 백그라운드로 안전하게 기록되는 동시에 지연 없이 새 탭 또는 유튜브 앱으로 연결된다.

**성공 기준**: 인앱 브라우저 환경에서 LCP ≤ 1.5초, 링크 탭 후 목적지 이동 지연 ≤ 200ms

---

#### SC-V02. 오프라인 현장 QR 코드 스캔 및 프로필 확인 (Phase 0·1)

**페르소나**: 정우진 (31세, 스타트업 리크루터)  
**상황**: 개발자 밋업 명찰 뒤편에 인쇄된 이준서의 MyLink QR 코드를 기본 카메라 앱으로 촬영함

1. 카메라 팝업 알림을 탭하여 Safari/Chrome 브라우저로 접속한다.
2. 이준서의 직무(`Frontend Engineer`), 한 줄 소개, 깃허브/이메일/포트폴리오 링크를 한눈에 스캔한다.
3. "GitHub" 링크를 눌러 프로젝트 레포지토리를 확인하고, 다시 뒤로 돌아와 "이메일 보내기" 링크를 탭한다.

**성공 기준**: QR 인식 즉시 로딩, 모바일 360px 좁은 화면에서도 텍스트 잘림 없는 완전 반응형 UI 제공

---

#### SC-V03. 프로필 재공유 및 신규 크리에이터 바이럴 유입 (Phase 1)

**페르소나**: 박민지 (대학생 방문자)  
**상황**: 동아리 친구의 MyLink 페이지가 깔끔해서 다른 동기에게 추천하고, 본인도 직접 만들어보고 싶어짐

1. 퍼블릭 페이지 우측 상단의 **[공유]** 아이콘을 눌러 "링크 복사"를 통해 카카오톡 단체방에 공유한다.
2. 페이지 최하단에 작고 세련되게 노출된 **"나도 MyLink 만들기 🚀"** 푸터 배너를 발견한다.
3. 배너를 탭하여 랜딩 페이지(`/`)로 이동한 뒤, 본인의 계정 생성(SC-U01) 단계로 자연스럽게 전환된다.

**성공 기준**: 퍼블릭 뷰어의 푸터 배너 클릭을 통한 가입 전환(K-Factor 바이럴 지표 추적 가능)

---

#### SC-V04. 예외 상황 처리: 비활성 링크 및 존재하지 않는 핸들 (Phase 1)

**페르소나**: 강태훈 (일반 웹 서핑 사용자)  
**상황**: 철자가 틀린 잘못된 핸들 주소(`mylink.app/@wrong_user`)로 접속함

1. 서버는 404 전용 페이지(`S-08`)를 렌더링한다.
2. 단순 브라우저 에러가 아닌, 친절한 일러스트와 함께 *"해당 프로필을 찾을 수 없어요. 주소를 다시 확인해 주세요"* 메시지가 뜬다.
3. 바로 아래 **[MyLink 홈으로 이동]** 및 **[이 핸들로 내 페이지 만들기]** 버튼이 제공되어 이탈을 방지한다.
4. 소유자가 비활성화(OFF)한 링크는 방문자 화면에서 아예 목록에서 누락되어 깔끔한 상태만 노출된다.

**성공 기준**: 잘못된 URL 진입 시 무한 로딩이나 깨진 화면 없이 0.5초 이내 전용 404 안내 화면 노출

## 6. 기능 상세 (Functional Requirements)

### F-01 인증 (Phase 1)

| 항목 | 상세 |
|---|---|
| 제공 방식 | Supabase Auth — OAuth (Google, GitHub, Kakao), 이메일+패스워드 |
| 세션 | Supabase JWT, Refresh Token 자동 갱신 |
| 비밀번호 정책 | 8자 이상, 영문+숫자 혼합 |
| 이메일 인증 | 신규 이메일 가입 시 인증 메일 발송 필수 |
| 탈퇴 | 계정 삭제 시 연관 링크·프로필·통계 데이터 즉시 파기 |

### F-02 핸들 설정 (Phase 1)

- 형식: `[a-z0-9_]`, 3~30자
- 예약어(`admin`, `api`, `login` 등) 사용 불가
- 변경: 30일에 1회 허용 (무분별한 스쿼팅 방지)
- 삭제된 핸들: 14일 쿨다운 후 재사용 가능

### F-03 프로필

| 필드 | 타입 | 제약 |
|---|---|---|
| handle | string | 영문·숫자·언더스코어, 3~30자 |
| display_name | string | 최대 50자 |
| bio | string | 최대 160자 |
| avatar | image | WebP 권장, 최대 2MB, 1:1 비율 권장 |

### F-04 링크

| 필드 | 타입 | 제약 |
|---|---|---|
| title | string | 최대 60자 |
| url | string (URL) | `https://` 강제, 유효 URL 검증 |
| icon | emoji / 이미지 | 이모지 선택 또는 직접 업로드 |
| is_active | boolean | 기본 true |
| sort_order | integer | DnD 시 재정렬 |

- 1계정 최대 링크 수: **30개** (MVP)
- URL 붙여넣기 시 Open Graph Title 자동 채우기 시도

### F-07 퍼블릭 페이지

- 경로: `mylink.app/@{handle}` (Phase 1) / `/` (Phase 0 로컬)
- 비로그인 접근 허용, SEO 대응 (`og:title`, `og:image` 메타 태그)
- 비활성(`is_active = false`) 링크는 렌더링에서 제외
- 링크 클릭 시 클릭 이벤트 기록 후 해당 URL로 새 탭 이동

### F-09 기본 통계 (Phase 1)

| 지표 | 설명 |
|---|---|
| 페이지 뷰 | 퍼블릭 페이지 접근 시 1회 기록 (동일 IP 1시간 내 중복 제거) |
| 링크 클릭 | 링크 클릭 시 비동기 기록 (사용자 UX 지연 없음) |
| 조회 기간 | 최근 30일 집계, MVP에서는 날짜별 차트 미제공 |

| 레이어 | 기술 |
|---|---|

| **배포** | Vercel (Edge Network, ISR) |

### 전역 상태 관리 전략

> MyLink 규모에서는 **Redux·Zustand 같은 별도 전역 스토어를 사용하지 않는다.**  
> 상태 종류별로 아래 방식을 따른다.

| 상태 종류 | 관리 방법 | 비고 |
|---|---|---|
| 인증 세션 | Supabase SSR + `useUser()` 훅 | Phase 1 |
| 서버 데이터 (링크·프로필) | Server Components fetch + Server Actions + `revalidatePath` | Phase 1 |
| localStorage 데이터 | 커스텀 훅 (`useLocalStorage`) + `useState` | Phase 0 |
| DnD 낙관적 UI | React 19 `useOptimistic` | 즉각 반응 후 서버 동기화 |
| 토스트·모달 등 UI 상태 | React Context + `useState` | 앱 전역 공유 필요한 것만 |

**Zustand 도입 검토 시점**: 클라이언트 전용 복잡한 다단계 폼, 실시간 협업, 오프라인 PWA 큐잉이 필요해지는 시점.

## 9. 데이터 모델 (ERD 요약)

### Phase 0 — localStorage 스키마

```ts
interface MyLinkData {
  profile: {
    handle: string;
    display_name: string;
    bio: string;
    avatar_url: string; // base64 또는 빈 문자열
  };
  links: Array<{
    id: string;        // crypto.randomUUID()
    title: string;
    url: string;
    icon: string;      // 이모지 or 이미지 URL
    is_active: boolean;
    sort_order: number;
  }>;
}
// localStorage key: "mylink_data"
```

### Phase 1 — PostgreSQL (Supabase)

```
users (Supabase Auth)
  └── profiles
        ├── id (FK → users.id)
        ├── handle        UNIQUE
        ├── display_name
        ├── bio
        ├── avatar_url
        └── handle_changed_at

profiles
  └── links
        ├── id
        ├── profile_id    FK
        ├── title
        ├── url
        ├── icon
        ├── is_active
        └── sort_order

link_events
  ├── id
  ├── link_id / profile_id
  ├── event_type        ("view" | "click")
  ├── ip_hash           (SHA-256, PII 최소화)
  └── created_at
```
