## 1. 배경 및 목적 (Background & Objective)

링크트리(Linktree)는 SNS 바이오 칸에 들어가는 링크 집합 페이지로, 크리에이터·학생·개인 모두가 손쉽게 "내 모든 채널"을 한 곳에 모아 공유할 수 있게 해 준다.

**MyLink**는 이 링크 인 바이오 카테고리의 국내 클론 서비스로, 다음 목표를 가진다.

- **누구나** 간편 가입 후 나만의 퍼블릭 프로필 페이지(`mylink.app/@handle`)를 만든다.
- 링크 관리를 **모바일에서도 쉽고 직관적**으로 할 수 있게 한다.
- **토스 디자인 시스템(TDS)** 기반의 깔끔하고 신뢰감 있는 UI를 제공한다.
- 추후 분석·수익화·API 기능을 올릴 수 있는 **확장 가능한 기반**을 마련한다.

|---|---|---|

## 4. 사용자 스토리 (User Stories)

### 인증 & 온보딩 (Phase 1)

```
US-01  비가입자로서, 구글 계정 하나로 30초 안에 가입을 완료하고 싶다.
       → 소셜 로그인 후 핸들 설정 화면 진입까지 화면 수 3개 이하.

US-02  가입자로서, 내 @handle 이 이미 사용 중인지 실시간으로 확인하고 싶다.
       → 타이핑 중 중복 여부 즉시 표시(debounce 500ms).
```

### 링크 관리

```
US-03  사용자로서, 링크를 새로 추가할 때 URL만 붙여넣으면
       제목이 자동으로 채워지면 좋겠다. (OGP meta fetch)

US-04  사용자로서, 화면에서 링크를 위아래로 드래그해
       노출 순서를 바꿀 수 있어야 한다.

US-05  사용자로서, 링크를 ON/OFF할 수 있어서
       삭제하지 않고 임시로 숨길 수 있어야 한다.
```

### 퍼블릭 페이지 & 공유

```
US-06  방문자로서, mylink.app/@handle 에 접근하면
       프로필 사진·이름·소개·링크 목록을 볼 수 있어야 한다.

US-07  사용자로서, QR 코드를 다운로드받아 명함·포스터에 붙이고 싶다.
```

### 통계 (Phase 1)

```
US-08  로그인 사용자로서, 대시보드에서 지난 30일간
       페이지 방문자 수와 링크별 클릭 수를 확인하고 싶다.
```

## 5. 사용자 시나리오 (User Scenarios)

> 실제 사용자가 처한 맥락과 단계별 흐름을 묘사한 시나리오예요.  
> 개발·디자인 의사결정의 기준으로 활용합니다.

---

### 👤 소유자 시나리오 (Owner)

> 프로필을 만들고 관리하는 사람의 관점

---

#### SC-01. 첫 방문 & 프로필 세팅 (Phase 0)

**페르소나**: 김예현 — 컴공과 1학년, SNS 바이오에 링크 하나만 넣기 아쉬운 새내기  
**상황**: 수업이 끝나고 강의실에서 폰으로 접속

1. 친구에게 mylink 링크를 받아 처음 접속한다.
2. 빈 프로필 화면이 뜨고 "아직 설정된 프로필이 없어요" 안내가 보인다.
3. **프로필 편집** 버튼을 눌러 편집 화면(`/edit`)으로 이동한다.
4. 이름(`김예현`), 한 줄 소개(`컴공과 1학년 새내기 👩‍💻`), 아바타 이모지를 입력한다.
5. **저장** → localStorage에 기록되고 프로필 페이지(`/`)로 돌아온다.
6. 자신의 프로필이 예쁘게 표시된 것을 확인하고 링크 추가를 시작한다.
7. `+ 링크 추가` → GitHub URL을 붙여넣자 제목이 자동으로 채워진다.
8. 이모지 아이콘(`🐙`)을 선택하고 저장한다.
9. 같은 방식으로 블로그, 인스타 링크를 추가한다.

**성공 기준**: 첫 접속 후 프로필 + 링크 3개 추가까지 5분 이내 완료

---

#### SC-02. 링크 순서 변경 & 임시 숨김 (Phase 0)

**페르소나**: 김예현  
**상황**: 깃허브 링크를 가장 위로 올리고, 아직 완성 안 된 블로그는 잠깐 숨기고 싶다

1. 편집 페이지(`/edit`)에 진입한다.
2. 블로그 링크 옆 **토글**을 눌러 비활성화한다.
   - 링크가 회색으로 바뀌고 "숨김" 상태로 표시된다.
3. 깃허브 링크를 **길게 누른 후 위로 드래그**해 첫 번째 위치로 옮긴다.
4. 손을 떼면 즉시 순서가 반영된다(낙관적 업데이트).
5. 저장 없이 자동 반영, 프로필 페이지에서 변경된 순서가 보인다.

**성공 기준**: 드래그 반응이 자연스럽고 손 뗀 뒤 0.3초 이내 UI 확정

---

#### SC-03. 프로필 공유하기 (Phase 0)

**페르소나**: 김예현  
**상황**: 동아리 소개 자리에서 내 프로필을 빠르게 공유하고 싶다

1. 프로필 페이지(`/`) 상단 **공유** 버튼을 탭한다.
2. 선택지가 뜬다:
   - **링크 복사** → 클립보드에 복사되고 토스트("링크가 복사되었어요")가 뜬다.
   - **QR 코드** → QR이 모달로 표시되고 이미지로 저장할 수 있다.
3. QR을 선택해 이미지를 카카오톡 채팅에 전송한다.
4. 동아리 후배가 QR을 스캔해 프로필을 확인한다.

**성공 기준**: 공유 버튼 탭부터 QR 이미지 저장까지 3탭 이내

---

#### SC-04. 신규 가입 & 핸들 선택 (Phase 1)

**페르소나**: 이준서 — 사이드 프로젝트를 막 시작한 개발자  
**상황**: 노션 포트폴리오·깃허브·유튜브 링크를 한 곳에 묶어 공유하고 싶다

1. mylink.app 랜딩 페이지에서 **"지금 시작하기"** CTA를 클릭한다.
2. 구글 소셜 로그인을 선택하고 계정 동의를 마친다.
3. 핸들 입력 화면이 뜬다. `@junseop` 을 입력하자 "이미 사용 중인 핸들이에요" 메시지가 뜬다.
4. `@junseop_dev` 로 변경하자 "사용 가능한 핸들이에요 ✅" 로 바뀐다.
5. **확인** → 대시보드(`/dashboard`)로 진입, 빈 링크 목록이 보인다.
6. 링크를 차례로 추가하고 프로필 설정에서 아바타를 업로드한다.
7. `mylink.app/@junseop_dev` 로 접속해 완성된 페이지를 확인한다.

**성공 기준**: 랜딩 접속 → 핸들 확정까지 30초 이내

---

#### SC-05. 링크 일괄 관리 & 재정비 (Phase 1)

**페르소나**: 최유리 — 인스타 마케터, 시즌마다 링크 구성이 바뀐다  
**상황**: 행사가 끝나 임시 링크를 정리하고 새 캠페인 링크를 추가한다

1. 대시보드(`/dashboard`)에 로그인한다.
2. "여름 이벤트 폼" 링크의 **토글**을 꺼서 비활성화한다 (삭제 대신 보관).
3. **+ 링크 추가** → 새 캠페인 URL을 붙여넣는다.
4. 자동 완성된 제목을 수정하고 이모지(`🎉`)를 선택한다.
5. 새 링크를 드래그해 맨 위로 올린다.
6. 프로필 페이지에서 변경 결과를 미리 확인한다.

**성공 기준**: 전체 정비 작업 3분 이내 완료

### 🌐 방문자 시나리오 (Visitor)

> 로그인 없이 공개 프로필을 조회하는 사람의 관점

---

#### SC-06. 프로필 조회 & 링크 클릭 (Phase 1)

**페르소나**: 박민지 — 이준서의 발표를 듣고 포트폴리오가 궁금한 동료  
**상황**: 발표 자리에서 받은 QR을 스캔해 프로필을 확인한다

1. QR 스캔 → `mylink.app/@junseop_dev` 로 이동한다.
2. 프로필 사진·이름·소개가 로드된다 (LCP ≤ 1.5s).
3. 링크 목록에서 **노션 포트폴리오**를 탭한다.
4. 클릭 이벤트가 백그라운드에서 기록되고, 새 탭으로 노션 페이지가 열린다.
5. 이준서는 다음 날 통계 화면에서 "어제 노션 링크가 5번 클릭됐어요"를 확인한다.

**성공 기준**: 링크 클릭 후 새 탭 열리는 지연 ≤ 200ms, 통계 기록 누락 없음

## 6. 기능 상세 (Functional Requirements)

### F-01 인증 (Phase 1)

| 항목 | 상세 |
|---|---|
| 제공 방식 | Supabase Auth — OAuth (Google, GitHub, Kakao), 이메일+패스워드 |
| 세션 | Supabase JWT, Refresh Token 자동 갱신 |
| 비밀번호 정책 | 8자 이상, 영문+숫자 혼합 |
| 이메일 인증 | 신규 이메일 가입 시 인증 메일 발송 필수 |
| 탈퇴 | 계정 삭제 시 연관 링크·프로필·통계 데이터 즉시 파기 |

### F-02 핸들 설정 (Phase 1)

- 형식: `[a-z0-9_]`, 3~30자
- 예약어(`admin`, `api`, `login` 등) 사용 불가
- 변경: 30일에 1회 허용 (무분별한 스쿼팅 방지)
- 삭제된 핸들: 14일 쿨다운 후 재사용 가능

### F-03 프로필

| 필드 | 타입 | 제약 |
|---|---|---|
| handle | string | 영문·숫자·언더스코어, 3~30자 |
| display_name | string | 최대 50자 |
| bio | string | 최대 160자 |
| avatar | image | WebP 권장, 최대 2MB, 1:1 비율 권장 |

### F-04 링크

| 필드 | 타입 | 제약 |
|---|---|---|
| title | string | 최대 60자 |
| url | string (URL) | `https://` 강제, 유효 URL 검증 |
| icon | emoji / 이미지 | 이모지 선택 또는 직접 업로드 |
| is_active | boolean | 기본 true |
| sort_order | integer | DnD 시 재정렬 |

- 1계정 최대 링크 수: **30개** (MVP)
- URL 붙여넣기 시 Open Graph Title 자동 채우기 시도

### F-07 퍼블릭 페이지

- 경로: `mylink.app/@{handle}` (Phase 1) / `/` (Phase 0 로컬)
- 비로그인 접근 허용, SEO 대응 (`og:title`, `og:image` 메타 태그)
- 비활성(`is_active = false`) 링크는 렌더링에서 제외
- 링크 클릭 시 클릭 이벤트 기록 후 해당 URL로 새 탭 이동

### F-09 기본 통계 (Phase 1)

| 지표 | 설명 |
|---|---|
| 페이지 뷰 | 퍼블릭 페이지 접근 시 1회 기록 (동일 IP 1시간 내 중복 제거) |
| 링크 클릭 | 링크 클릭 시 비동기 기록 (사용자 UX 지연 없음) |
| 조회 기간 | 최근 30일 집계, MVP에서는 날짜별 차트 미제공 |

## 6. 비기능 요구사항 (Non-Functional Requirements)

| 카테고리 | 요구사항 |
|---|---|
| **성능** | 퍼블릭 페이지 LCP ≤ 1.5s (3G 기준), TTI ≤ 3s |
| **가용성** | 월 99.5% 업타임 목표 |
| **보안** | XSS 방지, URL 화이트리스트/검증, Supabase RLS 정책 적용 |
| **접근성** | WCAG 2.1 AA 기준 준수 (키보드 탐색, 색상 대비) |

### 전역 상태 관리 전략

> MyLink 규모에서는 **Redux·Zustand 같은 별도 전역 스토어를 사용하지 않는다.**  
> 상태 종류별로 아래 방식을 따른다.

| 상태 종류 | 관리 방법 | 비고 |
|---|---|---|
| 인증 세션 | Supabase SSR + `useUser()` 훅 | Phase 1 |
| 서버 데이터 (링크·프로필) | Server Components fetch + Server Actions + `revalidatePath` | Phase 1 |
| localStorage 데이터 | 커스텀 훅 (`useLocalStorage`) + `useState` | Phase 0 |
| DnD 낙관적 UI | React 19 `useOptimistic` | 즉각 반응 후 서버 동기화 |
| 토스트·모달 등 UI 상태 | React Context + `useState` | 앱 전역 공유 필요한 것만 |

**Zustand 도입 검토 시점**: 클라이언트 전용 복잡한 다단계 폼, 실시간 협업, 오프라인 PWA 큐잉이 필요해지는 시점.

## 8. 데이터 모델 (ERD 요약)

### Phase 0 — localStorage 스키마

```ts
interface MyLinkData {
  profile: {
    handle: string;
    display_name: string;
    bio: string;
    avatar_url: string; // base64 또는 빈 문자열
  };
  links: Array<{
    id: string;        // crypto.randomUUID()
    title: string;
    url: string;
    icon: string;      // 이모지 or 이미지 URL
    is_active: boolean;
    sort_order: number;
  }>;
}
// localStorage key: "mylink_data"
```

### Phase 1 — PostgreSQL (Supabase)

```
users (Supabase Auth)
  └── profiles
        ├── id (FK → users.id)
        ├── handle        UNIQUE
        ├── display_name
        ├── bio
        ├── avatar_url
        └── handle_changed_at

profiles
  └── links
        ├── id
        ├── profile_id    FK
        ├── title
        ├── url
        ├── icon
        ├── is_active
        └── sort_order

link_events
  ├── id
  ├── link_id / profile_id
  ├── event_type        ("view" | "click")
  ├── ip_hash           (SHA-256, PII 최소화)
  └── created_at
```
